Plan browser audio as named gameplay events implemented with Howler.js or Web Audio, not FMOD/Wwise. Cover only useful cues: input confirmation, success/failure, impact, UI, ambience and music states. Define trigger, loop/one-shot behavior, priority, volume relationship and transition condition. Adaptive music is warranted only when gameplay has meaningful state or intensity changes. Keep source and path executable: Web Audio/Howler synthesis or scheduling is project code and therefore uses a .js/.ts module path with an oscillator/noise/envelope/filter/loop recipe; real or prerendered .mp3/.wav/.ogg media uses fetch_media. Never label a binary audio path as web_audio.
